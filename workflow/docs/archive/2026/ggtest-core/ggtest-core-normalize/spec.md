## 背景与目标

- GGTEST 在比对 query 期望与实际结果前，须将列值规范化，并按需排序或做 MD5 哈希比对。
- **本切片目标**：实现结果规范化与比对原语——I/T/R 规范化、`nosort`/`rowsort`/`valuesort`、与官方 C 实现**逐字节兼容**的 MD5 哈希、以及 hash-threshold 语义。
- 可用**固定样例**验收，**不必真跑库**。

## 非目标

- 解析 sqllogictest 文件（属 `parser`）。
- 连接数据库、执行 SQL、skipif/onlyif/halt/label 运行时（属 `runner-sqlite`）。
- CLI、语料收集与官方语料端到端硬验收（属 `cli-corpus`；本切片可用语料中的期望哈希串作样例输入）。
- 变更官方哈希算法或另立非兼容哈希格式。

## 范围与可见行为

期望结果与实际结果均以「每个值一行」的规范化文本比对（一行结果的多列展开为多行值）：

| 类型 | 规范化规则 |
|---|---|
| I（整数） | 按 `%d` 格式化；NULL → `NULL`；无法解释为整数的值 → `0` |
| R（浮点） | 按 `%.3f` 格式化；NULL → `NULL`；无法解释为数值的值 → `0.000` |
| T（文本） | 按 `%s`；空串 → `(empty)`；码位 < 0x20 或 > 0x7E 的字符逐个替换为 `@`；NULL → `NULL` |

- 排序语义：`nosort` 保持输入行序；`rowsort` 以规范化后的整行为单位按字符串排序；`valuesort` 将全部值打散后按字符串排序（不保留行分组）。排序在比对（及哈希）之前进行。
- **哈希比对**：当结果值总数超过当前 hash-threshold（阈值 > 0 时生效），期望结果形如 `N values hashing to <md5>`；实际结果：将每个规范化值后接 `\n` 依次拼接，对拼接字节序列求 MD5（小写十六进制）。必须与原始 C 实现逐字节兼容（官方语料既有哈希为判据）。
- **hash-threshold**：由调用方传入（CLI 初值或文件内指令）；默认初值 **8**（Q5）。阈值 ≤ 0 时不做哈希形态比对，按全量规范化文本比对。

## 合同

### API / 接口

- **规范化 / 排序 / 哈希比对入口（合同级，签名细节属 Design）**：接受类型签名、排序模式、当前 hash-threshold、期望文本与实际原始行列值（或已展开值序列），产出通过/失败及差异摘要所需信息。
- 不依赖 JDBC 或具体数据库驱动。

### 数据 / 状态

- 输入：列类型签名（`I`/`T`/`R`）、排序模式、hash-threshold、期望侧文本、实际侧值。
- 输出：比对结论；失败时可提供期望 vs 实际的差异摘要素材。
- 本切片无跨调用持久状态；hash-threshold 由调用方传入。

### 错误与约束

- 不得偏离范围中的 I/T/R、排序与 MD5 约定。
- 继承全局约束见「开放问题 / 已决议」，勿重开。

## 验收（Given-When-Then）

前置环境：固定样例输入即可；无需真实数据库。官方语料中的哈希期望串可摘为样例。

### P0

- **P0-2 哈希兼容**：
  - Given 官方语料中包含 `N values hashing to <md5>` 期望的规范化值序列（如摘自 `select1.test` 的既有记录）及对应 hash-threshold
  - When 按合同规则规范化、拼接并计算 MD5
  - Then 计算出的 MD5 与语料中的期望值一致，证明与原始 C 实现逐字节兼容

- **P0-4 结果规范化**：
  - Given 分别覆盖 I 列的 NULL、R 列的浮点值（期望为 `%.3f` 形式）、T 列的空串（期望 `(empty)`）的规范化输入与期望文本
  - When 执行规范化比对
  - Then 三条用例均按规范化规则判为通过

- **P0-5 排序模式**：
  - Given 一组行序与期望文本顺序不同的规范化行，以及对应期望
  - When 分别以 `rowsort` 与 `nosort` 声明并比对
  - Then `rowsort` 通过、`nosort` 失败，失败信息可支撑含差异摘要的报告

### P1

- **P1-3 valuesort**：
  - Given 一组以 `valuesort` 声明、期望值为全值排序结果的规范化输入
  - When 执行比对
  - Then 判为通过
